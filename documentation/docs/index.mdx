## Arsitektur ringkas

IPNU IPPNU ID bertindak sebagai **Authorization Server** dan **OpenID Provider**. Aplikasi yang terhubung adalah **Relying Party (RP)** sekaligus OAuth client. Alur yang didukung adalah Authorization Code dengan PKCE S256 untuk confidential client.

```text
Browser pengguna
  │
  ├─ 1. diarahkan ke /oauth/authorize + state + nonce + PKCE challenge
  │
IPNU IPPNU ID
  │
  ├─ 2. autentikasi, verifikasi akun, pemeriksaan assignment, dan persetujuan
  └─ 3. redirect ke callback RP membawa code + state + iss
       │
Server RP
  ├─ 4. tukar code + verifier + client secret di /oauth/token
  ├─ 5. validasi ID token RS256 melalui discovery/JWKS
  └─ 6. buat sesi lokal aplikasi
```

:::important Batas kepercayaan
Cookie sesi portal IPNU IPPNU ID bukan sesi aplikasi Anda. Setelah callback berhasil, RP wajib membuat dan mengelola sesi lokalnya sendiri. Access token juga bukan ID token: perlakukan access token sebagai opaque dan gunakan endpoint UserInfo.
:::

## Kemampuan yang tersedia

- Discovery OAuth 2.0 dan OpenID Connect.
- Authorization Code sekali pakai dengan masa berlaku 5 menit.
- PKCE wajib dengan `code_challenge_method=S256`.
- ID token bertanda tangan `RS256` dengan `kid` dan JWKS.
- Access token 1 jam serta refresh token 30 hari dengan rotation dan reuse detection.
- Scope identitas `openid`, `profile`, dan `email`.
- Kebijakan akses per client dengan assignment pengguna; role bisnis tetap milik aplikasi tujuan.
- Pencabutan satu grant aplikasi dari portal pengguna atau revocation endpoint.

## Model client saat ini

Client menggunakan autentikasi `client_secret_post`, sehingga secret hanya boleh berada pada server tepercaya. Aplikasi browser murni, mobile public client, atau SPA tanpa backend **tidak boleh** menanam client secret. Gunakan pola backend-for-frontend (BFF) atau backend aplikasi.
